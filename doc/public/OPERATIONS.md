# 部署与运维

根 README 提供本地启动、Docker 和 Nginx 示例。Compose 同栈模式使用容器服务名及内部端口；宿主机工具才使用映射端口。首次填入独立 PostgreSQL/Redis/管理员密码，已有数据库卷不会因改环境变量自动改密。

默认数据端口仅绑定 loopback；无认证的 ES 仅作本机开发示例。服务器部署应采用认证/TLS、适当网络隔离和最小端口暴露。若接入外部中间件，覆盖实际地址/认证并用 `docker compose up -d --no-deps proto` 启动应用，避免误启动本地示例服务。

只将反向代理入口暴露给用户；原型 runtime 的 CORS 由后端控制，代理不应增加重复 Access-Control-Allow-Origin。使用 HTTPS，保留 Vue history 回退和正确的 `/api` 剥离语义。

应用、系统图片、原型、上传临时目录需可写并按当前存储配置持久化。备份同窗口数据库、文件、配置和镜像版本；GC日志/堆转储可能含敏感内容，限制访问与保留周期，不公开上传。恢复或升级先在副本核验登录、权限、分享、文件关联与 readiness。

删除资源保留固定 30 × 24 小时，到期即不可从回收站恢复；数据库清理及磁盘删除异步执行，失败会留在持久化队列退避重试。升级时原有已到期墓碑立即符合清理条件。升级前停止全部旧写入及清理节点，先完成同窗口数据库和文件备份，并在隔离副本验证；不能混跑旧无限期保留节点和新清理节点。

应用自动 DDL 不提供破坏性回滚，也不创建数据库/schema。不能只回退 JAR 或删除数据重建代替恢复；停写后恢复同一时间点的数据库与文件，核验后再开放流量。

恢复演练必须停止所有写入副本及可能修改文件的后台进程，再取得数据库与文件副本。恢复到独立数据库和新文件根，核对安装身份、逻辑版本/全部修订/当前指针、分享与创建回执固定的修订、项目与版本的删除状态、预览文件与内容摘要；不能只比较行数。保留 `p_installation`、尚存的 `p_creation_receipt` 和 `p_file_cleanup`，不要因演练重置部署身份或丢弃已提交的文件清理任务。软删仍须备份所有持久化行、成员谱系及全部修订文件，不能仅按 30 天期限从备份清单排除数据。恢复后启动前应严格比对数据库、队列及文件摘要；启动后已到期记录与待办任务会继续清理，只能按本次明确验证的到期对象核对预期差集，不可忽略其他变化。活动占用应一致；仍保留资源的旧创建键保持冲突，永久清理资源及回执后原键去重终止，新的请求只能经当前权限与容量产生新 ID，不能复活旧 ID 或旧授权。

分享恢复还要核对 fixed/latest 模式、固定目标、revoked 和 configVersion，以及启停、密码和已轮换的密钥状态。latest 分享的空 revisionId 是合法策略，不能按待迁移 fixed 分享自动回填；预检脚本会分别计数，快照脚本输出不含明文凭据的完整分享摘要。恢复副本应验证永久撤销的分享和编辑前的旧凭据仍被拒绝，不能只验证新链接可打开。

可用 [独立进程验证工具](../../tools/verify-runtime.py) 演练隔离测试数据的重启、双进程和联合恢复，调用方式见[开发指南](DEVELOPMENT.md)。演练包含原型更新后的历史/当前修订及其分享和创建回执，另包含已删除的两次修订版本、随后删除的父项目与空项目、保留成员及旧凭据；恢复后核验文件 hash、释放后补位的新 ID、创建重放冲突以及管理/公开入口和旧凭据仍拒绝。另有独立的同 ID 逐项恢复组，与保留墓碑组一起备份；验证父子分别恢复、原创建键不重复扣额、旧凭据保持失效、新预览和分享可用，以及两进程新建/恢复争抢最后名额。独立到期组验证自动清理完整数据库图与文件、旧键去重结束后仅新建 ID、旧凭据仍拒绝；停写窗口另登记仅属于本次演练的已提交待办目录与任务，验证队列及文件共同备份、重启和新库新文件根恢复后的继续处理，只允许该组文件的精确预期差集。覆盖数据库、全部历史原型及本次上传的品牌图片和头像，恢复后核对图片引用与匿名下载内容。它不读取现有库或生产备份，也不替代真实部署中全部系统图片、配置、密钥和完整文件卷的备份策略；实际恢复仍需按原部署配置在副本核验。

升级软删版本前必须停止全部旧写入/清理节点，在副本核对 nullable `deleted_time`、活动占用及保留引用，再配套发布前后端。禁止混跑忽略软删标志或仍立即物理删除的旧版本；历史已经清理的内容无法从增列恢复。回收站恢复使用当前权限和容量，先恢复项目，再按需逐项恢复其版本，保留原 ID 与全部修订；恢复失败先检查30天期限、授权、父项目状态和名额，不手改删除标记。旧内部会话与旧分享仍无效，需重新申请预览或新建分享。未满30天的保留文件仍占用磁盘，到期文件由持久化队列在无引用后异步清理；不将人工删除目录当作释放业务额度。

## 邮箱身份与SMTP

访问者身份默认关闭，由分享管理员逐条开启。邮箱OTP需要SMTP；无SMTP时原型预览仍可用，邮箱验证明确显示不可用。管理员可对单个分享额外允许“未验证”低保障身份，访客须主动选择且界面保留未验证标识，不因邮件故障自动切换或标为已验证。固定分享的邀请通过管理员手动复制链接交付，邮件仍仅发必要验证码，不自动发送邀请或业务提醒。

SMTP客户端配置集中声明在 `bootstrap/src/main/resources/application.yml`：`spring.mail.host` 默认为空，未配置时不启用发送，也不在启动时连接服务商。填写标准 `spring.mail.host/port/username/password`，默认SMTP端口587、认证及STARTTLS启用且要求升级TLS，服务端身份校验开启；按服务商要求覆盖真实属性并使用有效TLS信任链。SMTPS需明确设置protocol为smtps及端口465，使用同一properties中的mail.smtps配置。发件地址使用 `spring.mail.properties.mail.smtp.from`（便利变量 `SMTP_FROM`），非空配置优先，空值取非空username，仍为空才取本机身份prototype-hub@localhost；必须填写服务商许可的单一完整邮箱，例如 `sender@example.invalid`，不能只填产品名称，也不接受显示名称、地址列表或换行。显式错误值不会静默改用认证账号，而是在连接前拒绝发送；若认证账号就是许可发件邮箱，可将 `SMTP_FROM` 留空复用它。连接、读、写默认各五秒，可用同级 `mail.smtp.connectiontimeout/timeout/writetimeout` 覆盖；这些是socket超时，不是DNS解析或第三方调用的整体耗时上限。SMTP/SMTPS的 `mail.smtp.localhost/mail.smtps.localhost` 缺省为localhost，避免为EHLO反查本机DNS；服务商要求FQDN时应在 `spring.mail.properties` 中显式填写并保留有效DNS配置。SMTP debug必须关闭。不确定发送不自动重试，失败仍占限额，不能标为已验证。

会话的 `spring.mail.properties.mail.from` 缺省复用上述发件地址，让MIME Message-ID直接取得发件域，避免生成邮件标识时反查本机DNS；显式填写的值会保留。该属性与SMTP的EHLO主机名职责不同，真实邮件服务仍需正确的服务端DNS、TLS及认证配置。

SMTP和SMTPS分别读取 `mail.smtp.from`、`mail.smtps.from` 作为envelope发件覆盖；没有协议专属覆盖时，客户端从邮件From头取得发件邮箱。直接配置这类原生属性时，应与许可发件身份保持一致，应用不会重写显式覆盖值。连接/认证成功只证明SMTP会话可用，不能证明MAIL FROM、收件人或DATA阶段会被服务商接受，也不能证明邮件已到达收件箱。

验证码发送失败对外仍返回503与 `PROTOTYPE_HUB_REVIEW_MAIL_UNAVAILABLE`，不返回邮件服务商原始异常。查看本地 `SmtpNotificationGateway` 的固定 `reason` 排障：`FROM_ADDRESS_INVALID` 检查最终发件邮箱；`AUTHENTICATION` 检查服务商SMTP开关及专用授权凭据；`TLS` 检查证书、信任链与协议端口；`DNS`、`CONNECTION`、`TIMEOUT` 检查网络和有限超时；`DELIVERY` 检查许可发件身份、收件策略与供应商额度；`CLIENT_CONFIGURATION` 检查本地邮件生成配置；`WORKER_REJECTED` 检查有界工作线程的生命周期或负载；`UNKNOWN` 结合安全异常类型继续定位。日志只包含类别、有界异常类型、协议与端口，不包含原始message/cause、邮箱、验证码或凭据。修改私密配置后重新加载资源并重启服务；保留TLS及服务端身份校验，不通过开启SMTP debug或自动重发来排障。

HTTPS终止或开发代理改写Host时，显式设置 `prototype-hub.review.trusted-origin=https://your-platform.example`；本地Vite通常为 `http://localhost:5173`，以浏览器实际地址为准，localhost与127.0.0.1不同。该值只能是单一完整HTTP/HTTPS origin，不含路径、查询、片段或账号；设置后仅接受它，不同时放开后台地址。缺省严格比较请求URI，不为此新增任意Forwarded信任或凭据CORS。

例如浏览器访问 `http://127.0.0.1:5173/share/...`，开发代理又把Host改为后端地址时，在本地私密配置中填写 `PROTOTYPEHUB_REVIEW_TRUSTEDORIGIN: 'http://127.0.0.1:5173'`；不要填写代理目标或分享完整路径。生产必须替换为实际HTTPS平台源，通用CORS的allowed-origins不能代替此配置。

邮箱身份接口的403保留不同原因：`PROTOTYPE_HUB_REVIEW_ORIGIN_DENIED`表示来源未被信任，检查上述精确源；`PROTOTYPE_HUB_REVIEW_COOKIE_REQUIRED`表示路径Cookie没有回传，检查浏览器Cookie、HTTPS及代理路径；`PROTOTYPE_HUB_REVIEW_CSRF_INVALID`表示当前Cookie和CSRF不匹配，重新载入身份验证。`PROTOTYPE_HUB_REVIEW_DENIED`仍表示分享或身份策略授权失效，不应通过放宽Origin、Cookie或CSRF解决。错误响应不会回显这些凭据或请求头。

`prototype-hub.review.cookie-secure` 默认true，仅本机HTTP测试设false。生产使用HTTPS；Cookie固定Path要求保留现有 `/api` 公开前缀及代理剥离语义，不能改为根路径解决代理问题。Cookie只发往review子路径，runtime与iframe不携带访客身份。

原生环境变量为 `SPRING_MAIL_HOST/PORT/USERNAME/PASSWORD`、`PROTOTYPEHUB_REVIEW_TRUSTEDORIGIN`、`PROTOTYPEHUB_REVIEW_COOKIESECURE`，也可沿Compose现有格式填写 `- "prototype-hub.review.trusted-origin=https://your-platform.example"`。主配置同时声明SMTP/SMTPS的认证、STARTTLS/SSL、服务端身份校验、连接/读/写超时及EHLO身份，发件地址可用 `SMTP_FROM`；TLS等map参数建议使用私有YAML或精确命令行属性，不提交真实密码，完整可用项以application.yml为准。模板见 `application-local.yml.example`。只有隔离的loopback测试接收端显式关闭认证/TLS，不沿用到生产。

备份全部九张评审表 `p_review_guest/p_review_unverified_guest/p_review_challenge/p_review_session/p_review_rate/p_review_invitation/p_review_thread/p_review_message/p_review_event`、相关 `p_creation_receipt`、分享配置及密钥，恢复副本核验未过期身份、邀请完整绑定、页面/线程归属、公开与内部可见性、原到期时间和旧撤销状态；不要单独恢复会话、邀请、消息或重置限频与回执。独立进程工具使用整库 `pg_dump/pg_restore`，完整性比较清单不等于备份的选表范围；仅有四张历史评审表的比较结果，不能证明其余五表已通过恢复验收。

九表恢复验收须在备份前通过真实接口建立非空的邮箱与未验证身份、待用/已消费/已撤销邀请、公开线程与回复、内部备注、状态事件及幂等回执。停写后比较行数与内容摘要；恢复到新数据库和两套新文件根后，先在启动应用前精确比较快照，再核验原身份、期限、配置代次、撤销状态、本人范围、内部备注隔离和原请求键重放。不得为通过演练重置到期时间、限频或授权；启动后的清理只能采用已明确验证对象的预期差集，不能忽略整张短期表。

恢复后新建的浏览器邀请与文字评审夹具用于验证实际服务可用，不代替备份前数据的持久性检查。自动化只用隔离本地SMTP和 `example.invalid` 夹具，不向真实客户发送测试邮件；报告仅保留有界行数、摘要和布尔结论，不输出邮箱、验证码、邀请原文、Cookie、正文或访问凭据。验收以本次完整进程报告为准，不由表清单或文档声明推定成功，也不代表外部SMTP、其他数据库/浏览器或目标生产部署已验。

邀请只适用于活动、已开启身份且修订有效的fixed分享；latest先由管理员明确选择固定修订。链接有效期为24小时与分享到期时间的较早者，服务端只保存凭据摘要，丢失后不能查询原始链接。创建受独立的项目60次/小时、收件邮箱5次/小时及60秒冷却限制，不退还或占用OTP发送额度。传递时按敏感链接处理，勿放进公开Issue、访问日志、截图或分析平台；公开外壳清除URL片段，凭据不进入原型iframe、本地存储或业务邮件。

访客须输入指定邮箱并完成新的OTP，即使已有邮箱身份也不能直接接受邀请；SMTP故障不会自动接受或改走未验证身份。邀请不是仅受邀者访问策略，普通分享入口保持原授权。分享配置/密钥变化、暂停、撤销、到期或回收均使旧待用邀请失效，邮箱访客停用再恢复也不能复活旧邀请。撤销邀请不能撤销已建立的会话，需要时停用该访客；已由SMTP受理的验证码无法收回，但失效邀请不能继续验证。没有人工身份关联或未验证身份恢复入口。

项目详情的访客管理沿分享查询/保存动作与项目SHARE权限，按email/unverified等级分别分页；已验证邮箱只显示脱敏值，低保障身份没有邮箱。停用即时阻断对应身份并撤销旧会话；邮箱身份还撤销验证码，重新启用要求新OTP。未验证身份即使重新启用也不能恢复旧Cookie或延长期限，丢失/退出/到期后不能按姓名、公司或邮箱自助找回，没有人工关联入口，需由管理员线下处理；新申请是另一身份，不自动合并为邮箱联系人。这些操作不改变匿名预览策略或退还限频额度。分享配置换代后须重新取得分享证明；仍带旧Cookie不妨碍明确申请另一随机身份，但不会恢复旧身份或旧访问凭据。

页面反馈默认关闭；管理员在有效fixed分享中开启身份及allowComment。历史空值按false，旧客户端省略或传null保留存储标志，身份关闭时有效反馈许可仍为false；新界面关闭身份同时关闭反馈。每次策略修改仍CAS并换代，不能靠恢复开关使旧会话重新授权。客户逐页接口仅能在同一分享和固定页面读取本人线程，不能靠另一分享或自填姓名找回；失效身份只允许明确重新验证，不自动重投文字。PM通过预览中的反馈入口手动查阅，查询和写入均要求项目EDIT及对应版本动作，项目查看者不能读取内部备注。

“全部页面反馈”仅汇总当前固定修订，原当前页反馈仍为默认入口。客户仍只能查看同一分享、本人guest及身份保障等级的线程；成员仍须项目EDIT和版本query，不新增角色、菜单或授权。总览只读且使用服务端真实分页，内部备注和分派不改变公开计数、排序或时间。未完成身份或待用邀请时不请求总览；完成原显式验证后可返回原筛选和页号。选择结果仍须校验当前manifest和完整三标识，再走原线程详情授权；打开总览不丢弃草稿或未知请求，跨目标放弃须明确确认。此入口不是平台全局工作队列，不新增配置、缓存、调度器或业务邮件用途。

线程链接只增加外壳URL的revisionId/pageId/threadId定位，不增加授权、表结构、配置或通知用途。成员仍须当前项目EDIT与版本query；客户仍须同一分享、固定页面和本人身份，密码、OTP及待用邀请流程均不能被链接跳过。链接无法恢复丢失的未验证身份，也不把PM链接自动转为客户链接。排查“线程不可用”时检查完整单值目标、当前分享与身份、许可及项目范围，不通过删掉错误参数自动回退首页；目标不在列表当前页或筛选中不代表线程不存在。复制链接不含访问凭据或邀请片段，普通页面链接仍可用；分享停用、撤销、到期、策略换代、身份到期及项目/版本回收后的旧链接继续拒绝，已失效数据不在界面保留。

反馈绑定选定页面，不跟随原型内部导航；访客初始投稿或已有线程的回复可手动附一张PNG/JPEG，正文仍必填，不增加成员创建客户线程的入口。外壳保留同目标草稿，身份过期后同一作者明确验证可保留文字、File和请求键再提交。网络结果未知时保留原请求键，先刷新核对并由用户决定重试，不换键自动重发；文字与附图创建不能用同键表达不同内容。内部备注不会修改公开线程时间、状态或排序。领域事件仅保留30天，现有周期每次最多删除50条；到期不删除线程、消息或身份历史，不建立业务发送任务，不新增SMTP用途、调度器或常驻队列。业务提醒未实现，不能把网页回复称为邮件已发送。

访客创建反馈时可明确采集根页面点、矩形或椭圆，保存为CSS整数像素位置和当时文档/视口尺寸；成员与访客仅在有权查看线程后手动定位。仅支持根文档，不穿透子frame；外壳按当前清单页面和encoded运行路径检查正常内部导航，路径变化或含query/hash时禁用采集/定位，原型不能据此指定另一页面。它是用户位置快照，不是对恶意原型的可信证明，也不持续跟踪元素。文档或视口尺寸任一不符时明确不可定位，不拉伸或自动迁移；同尺寸动态内容也可能与原位置不同。

几何与文字、可选图片及请求键一起保留在当前范围草稿中；同一作者验证往返或未知响应不自动重投，修改几何代表新意图。切换范围或实际作者后清理草稿和旧标记。原型只接收明确操作所需的几何与非授权通道信息，不接收反馈正文、身份、线程标识、图片或平台凭据。前后端及注入运行脚本应配套发布，保留原sandbox与no-referrer策略，不为定位加入allow-same-origin。

升级由EasyORM为p_review_thread增补可空anchor字段，以文本保存几何JSON，旧线程保持无锚点，不需新配置、依赖、调度器或SMTP用途。整库与整行内容摘要包含该列，存储清单仍为v3；原备份保留固定修订/页面归属，不把原有空锚点恢复结果当作非空几何恢复已验。回退前仍须验证同窗口数据库与文件副本，不能让旧客户端重写或猜测已存锚点。

线程负责人仅在成员预览中处理当前选定线程，使用版本query/save与当前项目EDIT，不增加菜单权限、角色、配置或通知用途。候选仅为当前启用的本项目owner/editor；有效管理员可沿既有管理例外操作，但没有项目绑定的管理员不是负责人候选。负责人不会授予资源访问权，公开分享和原型iframe不读取分派数据，公开时间、状态版本与消息计数不受影响。

停用账号、移除成员或降为viewer后，原负责人显示不可用，须显式清除或另选目标，不自动转交。同一账号重新启用或重新成为owner/editor可再次可用；删除账号则在原同步事务中清除所有分派并增加独立版本，失败回滚，不能通过重建相同ID找回分派。遇到409先刷新负责人并重新确认；未知结果保留原请求键手动重试，旧键重放返回当前投影而不恢复旧目标，不自动投稿或清空未发送的文字和图片。

升级由EasyORM增补p_review_thread的四个可空assignee/assignment字段；保留全表数据、账号和成员谱系、事件及回执，不手工清零并发版本。整库备份与整行摘要包含这些列，存储引用清单仍为v3，无新表或文件路径；已有演练结果不代表非空负责人已经通过恢复验收。实际恢复时应在副本核对负责人、独立版本及当前账号/成员可用性，不从旧快照自动新增授权。此功能没有全局待办、主副负责人、自动分派或业务提醒。

私有消息图片保存在原型存储根的 `projects/{projectId}/review-images/{attempt}/image`，首消息与回复复用同一存储和清理方式，与不可变发布目录隔离，不使用品牌图公共静态地址。限制为一张实际PNG/JPEG、原始字节不超过5 MiB、宽高各不超过16384且总像素不超过16000000；不支持SVG、自动截图或通用文件。图片继承消息public/internal范围，只能通过当前授权的POST接口取回，响应private/no-store；客户端手动查看并使用外壳Blob URL，原型iframe不接收图片或凭据。原文件名不保存，但原始图片可能含EXIF等信息，上传者应先自行处理敏感内容；已传给合法客户端的字节不能召回。

备份必须包含p_review_message的六个image_*字段、相关回执和整个原型存储根，不能只复制revision/site或品牌图片目录。非空图片恢复检查应在停写后比较数据库元数据与全文件hash，恢复到新数据库和新存储根，启动前精确核对，再使旧根不可用并用同一JAR按原权限读取原公开/内部图片、确认公开身份不能读取内部图。恢复后新上传的图不证明备份前图片已恢复；实际通过与否以绑定JAR和工具摘要的本次报告为准，不由文档推定。

明确回滚/未提交的上传候选会补偿或登记既有文件清理队列，UNKNOWN不得删除潜在已提交图片。突然断电/退出可遗留未引用候选，停写副本使用v3完整引用导出及离线审计处理；旧v2只供检查，不可执行完整修复。软删图片随固定30天保留，永久清理先登记review-image任务再删消息，提交后的worker重查包括内部和软删消息在内的所有引用；失败按既有策略退避，不能手动清空队列或猜路径删图。操作说明见[数据库与存储核验](DATA.md)。

升级时EasyORM只新增缺失的评审表、分享许可与会话/challenge字段，原邮箱表的必填约束不变，旧challenge的空invitation_id保持普通OTP语义。停止全部旧后端节点并配套发布前后端；不要混跑忽略反馈隔离、邀请绑定、身份等级、许可或停用状态的版本。备份/恢复须同时保留全部p_review_*、相关创建回执、enabled/config_version、verification_level、原expires_at与分享策略；不得只换回旧JAR作为安全回滚。八小时未验证身份及会话、限频窗口和到期邀请由既有周期逐表最多50行清理，不需要新增调度器或人工删表；恢复后仍按原期限失效，不能重置时间找回旧身份或邀请。版本/项目及相关修订永久清理同事务移除对应反馈、事件、邀请和回执，软删保持原分享撤销与30天文件回收规则。

当前通知传输仍位于原型模块，仅提供身份验证用途。邮件与短信传输后续会抽离为独立通知模块，复用同一NotificationGateway与配置；短信、通知管理界面和业务投递尚未实现。基础OTP保持独立可用，业务通知仍需各自的权限与用途检查，不把任意业务内容伪装验证码。

日志只收集白名单元数据并在落盘前脱敏；网关/CDN/错误日志同样不能记录完整分享URL、认证头或密码，也不得记录邮箱请求体、完整邮箱、验证码、Cookie或CSRF。安全事件按 [SECURITY](../../SECURITY.md) 私密报告。
