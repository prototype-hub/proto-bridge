# 开发与验证

使用 JDK 21 与项目 Maven Wrapper。模块职责遵循根 README；Java 包根为 `com.gaiys.proto`。实体放在 entity，服务与控制器沿模块现有结构组织，不按小功能过度拆分。新增框架适配复用公开 API/扩展点，不复制私有源码或使用反射/Unsafe绕过访问限制。

响应式请求保持 Mono/Flux 链路，阻塞文件操作放到已有受控调度边界；权限、数据范围和事务由后端执行。用户可见错误复用已有 i18n key；复杂安全/并发/兼容分支用简短注释说明原因，不记录令牌、密码或完整用户载荷。

普通持久化使用 EasyORM 的 `createQuery/createUpdate/createDelete`；关联查询使用 `QueryHelper`，JSON 属性条件使用官方 JSON term。条件、排序、分页和项目范围交给数据库，不拼接 SQL 或先读取全部数据再过滤。空 IN、空 NOT IN、缺失 JSON 属性和 SQL NULL 的行为须显式保留，不能让框架忽略空条件后扩大访问范围。幂等初始化使用官方 `upsert(...).doNothingOnConflict(true)`，不在同一失败事务中捕获唯一键错误后继续执行。

项目与版本列表的分页请求使用受限 DTO，只接收约定的页码、页大小、字面名称关键词和排序选项；不能直接将外部任意 terms、排序表达式或总量交给范围查询。计数与数据页复用同一授权条件，框架分页关闭越界自动重定位，稳定排序补 ID。Java 空白 owner 的旧数据约束通过官方 term 扩展点及结构化 jOOQ 表达式下推数据库，不能在取得分页后再用 Java filter 排除。版本修订数仅对本页 ID 作一次分组查询，空页不查询修订，禁止逐版本查询或加载 manifest。真实 PostgreSQL 回归验证分页 SQL、授权总量、25 种 Java 空白字符、字面通配符及页内聚合；代表性样本的执行计划不能替代生产规模与不同方言的性能验证。

并发写入使用同事务 `forUpdate()`，遵守稳定的用户 ID、项目、版本锁顺序；外部 I/O 不扩大锁事务。需要批次读取历史时按主键游标每批最多 100 条，完整消费并释放读取后再写入；跨页状态仅保留最小游标，不保留已消费的实体页。即时软删不删除文件；固定 30 天到期清理在项目→版本锁内登记持久化文件任务及删除图，每资源批次和文件重试每次最多 50 条。历史路径按游标分批消费，避免随修订数量无界积累。到期扫描游标在安装记录中持久化，先在短事务领取并推进下一页、释放安装锁后再逐项清理，防止失败头页饿死后续到期数据。单连接池、跨实例容量竞争、取消及事务回滚都是应保留的验证边界。DDL 中官方框架尚不能完整表达的注释和部分唯一索引由结构化 jOOQ API 生成，禁止使用 plain SQL 模板替代字符串拼接。支持范围与升级限制见[数据库说明](DATA.md)。

预览深链复用现有固定修订元数据、页面树与短期会话接口，不另造页面权限或公开历史授权入口。成员入口先校验真实项目范围，再以版本、项目、修订三元组校验关联；`pageId` 只映射本次不可变清单的唯一页面。前端只在缺少修订时解析一次 current，并将实际修订和页面规范化到 URL；显式无效目标不得回退。公开入口依原 `fixed/latest` 策略重新授权，链接修订与本次授权不符时显示失效，不用旧派生密钥持久化或放宽 latest 的历史访问。页面切换与修订切换分别处理，保留取消、代次隔离、会话到期清理及 opaque sandbox。合同与状态码见 [API 说明](API.md#修订页面深链)。

修订与分享的真实 PostgreSQL 集成回归应保留以下边界：R2 发布后重新签发显式 R1 会话仍读取 R1；同项目跨版本及跨项目修订 ID 不能用于元数据、页面树或会话；跟随分享的新授权解析 R2，已发 R1 授权保持 R1，暂停后两者及新信息请求均拒绝。浏览器用例另行验证刷新、前进后退、树选中与搜索、复制链接、错误目标及异步路由切换；后端合同通过不能替代浏览器行为验证。

修订比较复用相同授权边界，必须提供同版本两个明确修订；读取后释放数据库连接，再在既有 FileWork 内解析和计算两个最多 32 MiB 的清单，不逐文件查询数据库、读取磁盘或建立长期缓存。页面按精确路径取第一个别名，非文件夹且具有子节点的页面也要计入；SHA-256/大小与主页面名称决定变化，不推断重命名。完整计数先于 unchanged 筛选及两个独立分页，保留安全的越界处理。测试覆盖同修订、别名、嵌套页面、非法清单、跨范围和软删拒绝、权限撤销、单连接池及大量文件；浏览器另验双窗独立选页、刷新/前进后退、取消及窄屏操作。定位 URL 不含凭证，每窗沿固定修订接口重新授权，不改默认预览或公开分享。

软删以可空 `deletedTime` 表达，null 兼容旧活动行；使用 EasyORM 类型化条件，在 COUNT、分页及共同授权边界之前排除已删除父项目/版本。原始锁、引用与备份查询必须保留全部行；不可将活动服务替换进物理清理引用判断。软删事务保留谱系及修订文件，清理内部会话并终态撤销公开分享；旧不明清理任务只退避，新失败候选须明确来源并重验所有保留引用。回收站查询复用受限分页 DTO 与当前恢复权限，不能放宽普通读取边界。逐项恢复同一 ID，在与新建相同的锁内重验当前授权和额度，项目恢复不级联版本；不恢复旧授权或增加回执。集成回归覆盖事务回滚、跨副本新建/恢复最后名额竞争、父子顺序、各角色计数、删除时旧键409和恢复后同键安全重放。固定 30 × 24 小时到期条件在回收站 COUNT/分页及持锁恢复时统一生效，到期恢复404；后台同事务登记 `expired-snapshot` 队列并删除图，提交后才做文件 I/O。原始引用检查包含软删与旧别名，禁止项目根递归清理。测试应覆盖精确期限、数据库回滚、文件失败/取消/重启、共享引用、多于200条历史、单连接池、恢复与清理竞争及账号清理扫描后项目已被删除。永久清理资源和创建回执后旧键去重终止，新请求仍按当前权限和容量产生新 ID。

固定修订质量报告先完成当前项目 READ 与版本/修订关联查询，释放数据库读取后，在现有 FileWork 内按 manifest 路径读取实际 HTML/CSS；禁止额外目录遍历、远程抓取、脚本执行或扫描结果缓存。入口、页面/资源引用和中文路径是静态交付检查，平台注入脚本与外部/根绝对/片段/非文件协议按约定排除或显式计为未检查。单文档 2 MiB、累计 32 MiB、100,000 引用与 1,000 问题的固定预算限制单文档读取、累计解析和输出，截断、缺失或不可读时必须保留不完整状态；问题总数与省略数不能伪装成完整通过。问题中的用户路径/引用只作文本展示，客户端对同一份结果分页和导出 JSON，不添加报告表、后台任务或新权限。测试保留嵌套中文、相对路径和编码、HTML/CSS 解析、未知引用类别、损坏清单、文件丢失/符号链接与预算边界；真实 HTTP 验证固定 R1/R2、重复只读、单连接池、跨范围、撤权/停号及软删拒绝，浏览器验证修订切换、迟到响应、下载归属与窄屏。字段与静态检查限制见 [API 说明](API.md#固定修订交付包质量报告)。

本地日志的 LIKE 条件须在有界条件构造期准备，避免将用户通配符变成每条日志执行的回溯正则。`%` 可匹配换行，`_` 匹配单个字符，其他字符保持字面含义，ES 转换先转义反斜线再处理通配符。回归须保留合法短模式引起长时间回溯的反例、跨行、字面反斜线、星号/问号及否定操作；不能只用普通单行样本断言两个存储语义一致。

角色属性在 PostgreSQL 显式注册官方 JSON 条件特性；未适配方言必须拒绝该条件，避免静默忽略后扩大结果。所有权迁移、授权纪元轮换和删除账号时的所有权清除是内部授权维护，通过框架提供的上下文标记保留原创建、修改审计字段；用户主动编辑仍按正常审计规则处理。

```bash
./mvnw -B -ntp clean verify
python3 tools/verify-identifiers.py
```

邮箱身份沿既有分享授权和项目→版本锁扩展；访客命名空间独立平台用户，配置代次与分享派生密钥的摘要必须逐次匹配。OTP先写pending、事务外发SMTP、再锁内确认投递，BCrypt计算也不持锁；验证以事务结果提交错误次数或原子消费，之后才产生公开错误。限频使用持久状态，不以本机缓存回落。严格Origin、路径Cookie和CSRF共同构成专用可信外壳边界，不放宽iframe/CORS或全局客户端。真实集成测试保留本地SMTP/MIME、pending拒绝、邮箱恢复与隔离、并发一次消费、错误次数提交、凭据/Origin/CSRF拒绝及生命周期清理；所有邮箱都使用example.invalid，不能向真实收件人运行自动测试。

项目邮箱访客管理复用分享动作与项目SHARE能力，所有状态变更在项目锁事务内重验权限、归属和CAS；旧null保持有效/版本0。OTP准备、受理回写、消费与context都检查当前guest状态，启停同时移除旧挑战和会话，恢复必须新OTP。真实HTTP用延迟本地SMTP证明disable→restore期间已受理的邮件不能复活，触发器失败证明状态和身份图原子回滚，保留分页脱敏、权限、并发CAS和匿名预览边界。升级前必须停掉忽略该状态的旧节点，不允许混跑。

集成测试需要 Docker 与可用的测试中间件环境，不使用生产数据库。确需格式化时运行 `./mvnw spotless:apply` 后审阅差异。选择性回归须写明实际范围，不能把单类通过描述成全量通过。

独立进程验证使用实际打包 JAR，需要 macOS/Linux、JDK 21、Python 3.9 及以上版本与可用的 Docker CLI：

```bash
python3 tools/verify-runtime.py --jar bootstrap/target/bootstrap-1.0.0.jar --report /tmp/proto-runtime-report.json
```

工具自行创建随机 PostgreSQL 容器、测试数据库和私有临时目录，不接收已有数据库连接。它验证登录、上传、密码分享、完整进程重启、多进程容量竞争，以及停写后数据库、原型文件和系统图片的联合恢复；分享验证包含固定/跟随快照、启停后的旧 HTML/资源/页面树拒绝、密码替换与去除、过期配置版本、轮换链接和永久撤销。同一六阶段还验证两次修订后删除版本、随后删除父项目和另一空项目，释放占用后以新 ID 补位；重启和新库恢复后核对 tombstone、成员谱系、分享/回执关联与文件 hash，旧创建键仍409，管理/匿名新入口及旧内部/公开凭据仍拒绝。另保留独立的逐项恢复组：同 ID 恢复父项目、确认子版本仍删除，再恢复子版本，检查原修订与回执、旧凭据拒绝和新授权可用；双进程最后项目名额由新建与恢复竞争，重启及联合备份恢复后继续核对两组状态与文件。另建独立到期样本验证实际调度清理数据库图和文件，以及待办文件队列跨重启、同窗口备份和新库新文件根恢复后继续执行；原近期删除和恢复样本维持逐项身份及文件 hash 校验，只允许到期样本自身的预期文件差集。品牌图片及本人头像经实际文件接口上传，恢复后核对数据库引用、匿名下载与文件摘要。该演练使用本地共享文件根，不代表其他文件服务或生产配置已验证；结束时只清理自身资源。默认使用 `postgres:16-alpine`，可用 `--postgres-image` 指定拟验证的镜像，结果仅覆盖实际执行的数据库版本；`--java` 可指定 JDK 可执行文件的绝对路径，默认从 `JAVA_HOME` 或 `PATH` 查找。

同一演练还比较正常组及逐项恢复组的两个固定修订，在重启和联合恢复后重复检查真实 HTTP 结果；完整统计、unchanged 筛选、页面/文件独立分页、同 R1 比较不回退 current、跨项目修订及匿名拒绝都必须正确。文件 SHA 与已经匿名读取的实际运行字节核对，软删组的比较入口仍返回 404；这些检查不改动原保留文件或到期清理夹具。

同一演练通过真实打包接口检查正常组和恢复组的固定 R1/R2 质量报告，核对清单身份、5 个文件、4 份 HTML/CSS、9 个静态引用、固定预算和重复结果；完整原创样本没有缺失问题，平台 Inspector 不误报。重启和联合恢复重复验证，跨项目/缺失修订及匿名请求拒绝，软删修订报告入口为 404；工具自身的故障注入测试保证错误身份、预算、计数和不完整结果不能被验收为通过。

需要联合前端时，先在配套前端目录安装依赖并完成生产构建，再增加 `--frontend-dir /path/to/proto-bridge-ui`。工具向真实浏览器用例提供本次隔离实例的临时连接和样本，不加载用户本地应用配置。报告保留 JAR 摘要、样本摘要及检查结果，密码、令牌和分享密钥不进入报告；失败时生成权限受限的诊断日志，临时清理失败时记录待处理目录。报告和诊断均只在本地排查，不将运行数据或备份加入发行包。该原创多页 HTML 样本用于验证运行链路，不代表真实 Axure 导出包或生产环境兼容性。

同一运行演练启动只绑定127.0.0.1的SMTP接收端，验证真实OTP、Cookie属性及身份在进程重启、另一副本和数据库恢复后的关联，备份比较包含四张p_review_*表。运行演练还通过实际管理API停用/恢复访客，确认旧Cookie/未消费验证码失效且新OTP恢复同guest后，再检查跨进程与备份恢复。邮件只接受example.invalid，不转发外网；供Node浏览器测试读取的临时邮箱文件以0600权限原子写入，Cookie/CSRF、完整邮箱与验证码不进入报告，演练结束移除邮箱。前端专用流程读取同一临时邮箱完成发码、验码、重开恢复身份及退出，不通过产品接口暴露验证码。

工具自身的隔离、报告和清理边界可单独验证；设置已安装前端目录后，额外运行真实 Playwright CLI 超时/中断探针：

```bash
python3 -m unittest discover -s tools -p 'test_verify_runtime.py'
python3 -m unittest discover -s tools -p 'test_audit_storage.py'
PROTO_RUNTIME_PLAYWRIGHT_DIR=/path/to/proto-bridge-ui python3 -m unittest discover -s tools -p 'test_verify_runtime.py'
```

未设置该变量时两项真实 CLI 探针会明确跳过，不能计为已验证。探针使用自产 HTTP 服务验证清理，不代表实际平台浏览器业务测试通过。

正式分发使用 `bash tools/verify-open-source.sh` 执行完整发行门禁，包含上述工具自身的基础安全测试；设置 `PROTO_RUNTIME_PLAYWRIGHT_DIR` 时同时执行真实 CLI 生命周期探针。实际 JAR 与浏览器业务演练仍需单独运行。release-audit 与发行检查详见 [发布指南](RELEASE.md)。版本入口和组件核验见 [依赖基线](../DEPENDENCY_BASELINE.md)；测试报告生成在 target 内，不纳入公开源码导出。

本地实际配置从资源示例复制到 `config/application-local.yml` 并显式通过启动参数加载；该目录不公开。改名不移动既有原型存储目录，避免破坏分享与版本关联。
